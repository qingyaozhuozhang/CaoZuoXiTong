# F1–F3 实现与优化记录

## 范围声明

本轮仅围绕 F1 用户态入口跳转、F2 六个整数/指针参数和 F3 正常函数返回值捕获开展源码修复、性能调优与验收。保留旧接口，但不以现有基础测试结果推断已完成 F4–F7，也不宣称支持 ARM64。

## 与原始源码相比的主要修改

| 类型 | 位置 | 改动 | 目的 |
|---|---|---|---|
| 正确性 | `ludp.c:threads_refresh()` | 将退出线程清理参数改为真实线程 ID | 修复错用循环下标导致的线程表残留 |
| 正确性 | `ludp.c:sort_threads()` | 排序时同步交换 `tids`/`seized` | 避免线程 ID 和追踪状态错位 |
| 正确性 | `ludp.c:add_thread()` | 两数组成对分配、成功后再替换 | 避免部分扩容失败时损坏上下文 |
| 正确性 | `ludp.c:remote_syscall()` | 优先选择处于用户代码的可安全注入线程 | 避免在阻塞的 `pthread_join`/`futex` 现场强制注入导致错误的 syscall restart |
| 性能 | `ludp.c:mem_read()`/`mem_write()` | 大块复制优先使用 `process_vm_readv/writev`，失败时回退 | 降低目标进程远程内存拷贝的额外成本 |
| 资源 | `ludp.c:configured_ring_cap()` | 运行时配置 2 的幂容量 | 普通监控可降低事件缓冲区内存需求 |
| 可验证性 | `test_thread_state.c` | 多线程已存在、阻塞/非阻塞主线程测试 | 保证修复问题有可重复的回归测试 |
| 演示 | `demo_f123.c` | 完整的中文入口、六参数和返回值演示 | 便于答辩现场独立运行 |
| 工程 | `Makefile`、`evaluate.py`、`auto_tune.py` | 自动构建、测试、基准、候选参数选择 | 避免未经验证就把性能变化当成优化成功 |

## 实测结论与解释

执行 `make test` 和 `evaluate.py` 后的原始数值请查看 `../reports/benchmark.json`、`../reports/对照分析.md`；如果被测试的内核 uprobe 无权限/设备，报告必须明确写为 `SKIP`。

**重要：** 对照数据中，F1 单次探针额外开销在不同批次可能反而升高；这是必须保留并如实披露的观察。线程调度和虚拟 CPU 负载等因素会影响纳秒级结果，不能把单次回归测试的开销变化直接归因于 `process_vm_*` 代码。该优化只运行在 tracer 侧的内存访问和安装流程，**不改变每次探针命中执行的汇编代码**。

改进最明确的部分是：先前未覆盖的“主线程已在 `pthread_join` 阻塞而后附加 tracer”场景，新测试能够复现并在修复后通过；执行不安全远程 syscall 的场景被改为优先选择用户态线程，若无可选线程则拒绝执行，避免无条件损坏目标上下文。

## 仍需注意

- 当前自动调优只选择在候选中通过正确性检查的远程大块内存复制方式；不会自动改写汇编、改坏用户程序或为了达标删减测试。
- F3 依赖正常的函数返回过程，不能跨异常展开等非局部控制流。
- 不能把小环形缓冲的显式溢出误判成函数没有被命中。
- 不会偷偷调高 ptrace 权限，也不会在基准缺失时填入“uprobe 约 1500–3000ns”的参考数值冒充实测。
