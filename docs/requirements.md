# 需求与评审对应关系

## 1. 依据与交付范围

本项目面向 2026 年全国大学生计算机系统能力大赛操作系统设计赛西北区域赛的“轻量级用户态动态探针”赛题，难度 A、工程型。功能与指标依据赛题正文；README 结构依据团队提供的[大赛文档要求](https://shimo.im/docs/vVqRVbmLlaCXKoqy/read)中的“设计赛道文档大纲”。

本轮交付包括专业化文档、可复现演示和 A1 双架构实现。x86-64 与 ARM64 使用各自原生 Runner 执行相同验证流程，结果按提交和架构记录；交叉编译或模拟执行不代替原生性能验收。

## 3. 功能与量化证据

| 需求 | 交付与验证入口 | 验收边界 |
| --- | --- | --- |
| F1 动态库函数入口探针 | `probe_demo` 打印 x86 JMP / ARM B 入口跳转字节，`probe_abi_validation` 核验运行路径 | 仅受支持的指令可安全重定位 |
| F2 前六参数 | 演示 `[1,2,3,4,5,6]` 与函数实际调用对照 | SysV INTEGER 寄存器 / AAPCS64 X0–X5 原始值 |
| F3 返回值 | 演示整数返回 183、浮点返回 4.00，核验 call_id | 正常返回，复杂 ABI 需调用者解释 |
| F4 清理 | `probe_lifecycle_validation` 核验原始字节、映射回收和槽位复用 | 应用安全点；remove 与 detach 口径区分 |
| F5 动态开关 | `probe_lifecycle_validation` 对照启用、停用与再次启用的事件 | 已有事件和在途返回不会因停用消失 |
| F6 ≥16 个探针 | `multiprobe_validation` 实际触发并逐 ID 核验 | 注册表容量不等于已验证最大并发规模 |
| F7 多线程安全 | `probe_abi_validation`、`thread_signal_validation` 并发/信号测试 | 不承诺在任意指令位置热插拔 |
| A1 x86-64 + ARM64 | 两套指令与 trampoline 后端、双架构 CI | `3ffd736` 两架构原生 full / UBSan 均通过，见 [验证报告归档](archive/README.md)；后续提交需重新验证 |
| A2 条件过滤 | `probe_extensions_validation` 核验比较运算 | 单参数、无符号比较，不解引用指针 |
| A3 perf/ftrace 合流 | 真实用户态事件与 ftrace getpid 事件合流、TID/CPU/时间容差检查 | 新版双架构结果待取得；不覆盖所有 perf/kprobe 格式和长期漂移 |
| A4 目标进程函数调用 | `callback_validation` 回调、状态恢复、更新与忙时保护 | 回调限制及 CPU 条件见支持范围文档 |
| A5 热更新 | 配置、generation、非法输入和回滚测试 | 依赖安全点；回滚失败需要处理 |

完整测试内容、阈值和剩余验证项见 [测试与性能评估](testing.md)。

这些交付用于支持“文档完整性和 demo 质量 15%”的评审，不代表已经获得相应分数。

## 5. 评分口径说明

赛题正文包含两组权重：“评分权重”为基础功能 60%、正确性 25%、性能 15%、文档/demo 15%；“评审要点”为基础功能 50%、正确性 20%、性能 15%、文档/demo 15%。前者相加为 115%，两者不一致。

本项目不自行修正或合并上述权重；需求映射按功能条目和量化阈值建立，最终计分以组委会确认的正式规则为准。两处对文档与 demo 均列为 15%。
